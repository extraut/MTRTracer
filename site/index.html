Видно каждый узел. И где именно теряются пакеты.

MTRTracer прокладывает маршрут до любого сайта, игрового сервера или IP и держит его под наблюдением: потери и задержка на каждом хопе, джиттер, место узлов на карте, честный режим для VPN и журнал, по которому видно, что днём было хорошо, а вечером стало плохо.

Возможности

Всё, что делал WinMTR, и всё, чего ему не хватало

Одна программа вместо связки из tracert, ping, WinMTR, сайтов «где мой IP» и ручных записей в блокноте. Каждая цифра проверяема: за ней стоит сырой лог пакетов, а у каждой геоточки виден источник и дата.

Хопы со всей статистикой mtr

На каждый TTL свой поток, пакеты уходят параллельно, как в WinMTR. Задержка меряется таймером высокого разрешения с точностью до микросекунд, а не округляется до миллисекунды.

  • Несколько узлов на одном хопе (балансировка ECMP) видны отдельно, с долей ответов
  • Смена маршрута, серии потерь и обрывы попадают в события с точным временем
  • Если цель молчит на ICMP, включается TCP-пинг 443/80
  • Поиск Path MTU и сравнение DNS-серверов по кнопке

Карта, которая сверяется с физикой

Базы геолокации часто ставят магистральный роутер в город, где у оператора офис, а не туда, где стоит железо. MTRTracer опрашивает несколько источников и проверяет каждый по скорости света: за 1 мс задержки сигнал успевает пройти около 100 км туда и обратно в оптоволокне. Место, которое физически недостижимо, помечается, а не выдаётся за правду.

  • RIPE IPmap по реальным замерам RIPE Atlas, MaxMind GeoLite, DB-IP, имена роутеров, Cloudflare
  • Anycast-адреса вроде 1.1.1.1 ставятся у ближайшего узла, а не в стране регистрации
  • Плоская карта или глобус, офлайн-подложка Natural Earth внутри программы

VPN без самообмана

Через прокси-туннели вроде Xray, sing-box или Clash пошаговая трассировка невозможна: туннель передаёт только TCP и UDP, а на пинг часто отвечает сам за доли миллисекунды. Обычный трассировщик покажет красивые, но выдуманные цифры. MTRTracer это распознаёт и предлагает VPN-режим.

  • Находит процесс VPN-клиента и его сервер по таблице соединений
  • Трассирует настоящие хопы до сервера через физический адаптер
  • Меряет сквозную задержку до цели HTTP(S)-запросами через туннель
  • Показывает выход VPN и оценку участка «сервер → цель»

История: днём и вечером

Каждый запуск сохраняется сам: снимок раз в минуту и при остановке, хранение полгода. Видно, когда цель стала отвечать хуже, менялся ли маршрут и как выглядели те же хопы в прошлый раз.

  • График средней задержки и потерь по всем запускам цели
  • Пометка «маршрут изменился» между соседними запусками
  • Сравнение двух запусков бок о бок по каждому хопу с разницей
  • При новом запуске строка «В прошлый раз: …, сейчас: …»

Разбор, где проблема настоящая

Самая частая ошибка при чтении MTR: испугаться потерь на промежуточном хопе. Роутеры ограничивают ответы на ICMP, и если дальше пакеты проходят, это не проблема. MTRTracer разбирает таблицу по тем же правилам, что и опытный сетевик, и пишет выводы человеческим языком.

✓Маршрут стабилен: 0% потерь до цели, средняя задержка 25.6 мс.
iХоп 4: 31% потерь, но дальше пакеты проходят. Роутер ограничивает ответы ICMP, на трафик это не влияет.
!Задержка растёт на +19 мс между хопами 7 и 8. Часто это длинный магистральный канал.
!Потери 6% до цели начинаются на хопе 9 и сохраняются дальше. Вероятное место проблемы.

Честно

Где могут быть проблемы

Сетевая диагностика упирается в то, как устроен интернет. Вот что важно знать заранее, чтобы правильно читать результат.

Геолокация роутеров приблизительна

Обычно точность до города, иногда сотни километров. Проверка по скорости света отсекает невозможное, но не делает данные точными. Точки, которые не сходятся с задержкой, помечены знаком «?».

Прокси-туннель скрывает хопы

Через Xray, sing-box, Clash видно только путь до сервера VPN и сквозную задержку. Это свойство туннеля: никакая программа не увидит хопы за ним.

Роутеры режут ICMP

Потери и задержка на промежуточном хопе могут быть артефактом: роутер отвечает на пинг в последнюю очередь. Смотрите, сохраняется ли это до цели. Разбор подсказывает.

UDP-туннели не видны в таблице

WireGuard, Hysteria и другие UDP-протоколы не раскрывают адрес сервера в таблице соединений. Для VPN-режима его нужно один раз вписать вручную.

Linux: права на ICMP

Работает без root через ping-сокеты, если это разрешено настройкой ping_group_range (так по умолчанию в Ubuntu, Fedora, Debian 12, Arch). Иначе одна команда sysctl или setcap.

Антивирусы и неподписанный exe

Программа работает с сетью на низком уровне и перечисляет соединения процессов. Некоторые антивирусы настороженно относятся к такому неподписанному файлу. Исходники открыты, собрать можно самому.

Установка

Скачать или собрать самому

Готовые сборки лежат в GitHub Releases: их собирает GitHub Actions прямо из исходников репозитория, рядом лежат контрольные суммы SHA-256. Можно собрать и самому: одним скриптом, без Visual Studio, результат запускается без установки .NET.

  1. Скачать MTRTracer-windows-x64.exe со страницы релиза и запустить. Установка не нужна, нужен WebView2 Runtime (в Windows 11 он уже есть). Файл не подписан, поэтому SmartScreen может спросить подтверждение: «Подробнее» → «Выполнить в любом случае».

    Открыть релизы на GitHub

  2. Или собрать из исходников. Один раз поставить инструменты сборки:

    winget install Microsoft.DotNet.SDK.10
winget install OpenJS.NodeJS.LTS

  3. В папке проекта запустить сборку:

    powershell -ExecutionPolicy Bypass -File .\build.ps1

  4. Готовый файл: dist\MTRTracer.exe. Нужен WebView2 Runtime, в Windows 11 он уже есть. Флаг -Linux соберёт заодно и Linux-версию.

  1. Скачать mtrtracer-linux-x64.tar.gz (или arm64) со страницы релиза. Для окна нужен WebKitGTK: sudo apt install libwebkit2gtk-4.1-0 libnotify4.

    Открыть релизы на GitHub

  2. Или собрать из исходников. Инструменты сборки и окно (пример для Ubuntu/Debian):

    sudo apt install dotnet-sdk-10.0 nodejs npm libwebkit2gtk-4.1-0 libnotify4

  3. Собрать архив:

    ./build.sh                 # linux-x64
./build.sh --arch arm64     # Raspberry Pi, ARM-серверы

  4. Установить для своего пользователя, без root (архив из релиза или из dist-linux/):

    tar -xzf mtrtracer-linux-x64.tar.gz
cd linux-x64 && ./install.sh

  5. Запуск из меню приложений или командой mtrtracer. Без WebKitGTK: mtrtracer --browser, интерфейс откроется в браузере.

Вопросы

Коротко о частом

Почему через VPN все хопы показывают таймаут или 0 мс?

Прокси-туннель не пропускает пакеты с малым TTL и часто сам отвечает на пинг. Включите VPN-режим: он покажет настоящие хопы до сервера VPN и честную задержку до цели через туннель.

Нужны ли права администратора?

Нет. На Windows используется системный ICMP API, на Linux непривилегированные ping-сокеты. Только если в вашем Linux они запрещены, понадобится одна команда sysctl или setcap.

Почему на промежуточном хопе 40% потерь, а у цели 0%?

Роутер ограничивает ответы на ICMP, а транзитный трафик пропускает. Это нормально. Проблема настоящая, только если потери сохраняются до самой цели.

Насколько точна карта?

Обычно до города. Программа проверяет каждую точку по физике: если база ставит узел туда, куда сигнал не успевает долететь, точка помечается «?». Источники и причины видны в деталях хопа.

Можно ли сравнить, как было днём и вечером?

Да. Каждый запуск сохраняется в историю, во вкладке «История» есть график по запускам и сравнение двух запусков по хопам.
