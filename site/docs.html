Документация

Всё о том, как MTRTracer собирается, что показывает, откуда берёт каждую цифру и как читать результат. Поиск слева ищет по всему тексту.

Обзор

MTRTracer непрерывно отправляет ICMP-пакеты к цели с растущим TTL (числом хопов, которые пакет может пройти). Каждый роутер на пути, у которого TTL истёк, отвечает сообщением «время жизни истекло», и так становятся известны все узлы маршрута. Пакеты уходят раундами, статистика по каждому хопу копится и обновляется в реальном времени, как в WinMTR и mtr.

Поверх этого программа:

  • даёт выбрать, через какой сетевой адаптер отправлять пакеты, и объясняет, как устроены VPN-туннели;
  • определяет имя, сеть (AS) и место каждого узла по нескольким источникам и проверяет место по скорости света;
  • рисует маршрут на карте и анимирует пакеты;
  • пишет каждый пакет в лог с точностью до микросекунд, фиксирует события и разбирает результат словами;
  • сохраняет историю и сравнивает запуски;
  • показывает, какие программы держат сетевые соединения.

Есть версии для Windows (окно на WebView2) и Linux (окно на WebKitGTK или браузер). Интерфейс и логика одинаковые.

Сборка на Windows

Один раз поставьте инструменты:

winget install Microsoft.DotNet.SDK.10
winget install OpenJS.NodeJS.LTS

Затем в корне проекта:

powershell -ExecutionPolicy Bypass -File .\build.ps1

Скрипт по порядку:

  1. устанавливает зависимости интерфейса (npm ci) и собирает его в ui\dist;
  2. прогоняет юнит-тесты (они не выходят в сеть);
  3. публикует dist\MTRTracer.exe: один самодостаточный файл со встроенным интерфейсом.
ПараметрЧто делает

То же вручную:

dotnet test src\MTRTracer.Tests -c Release

Разработка

Интерфейс можно смотреть в обычном браузере на демо-данных, без сети и без C#-части:

cd ui && npm run dev    # http://localhost:5173

В этом режиме работает встроенный симулятор (ui/src/bridge/mock.ts): адаптеры и туннель, трассировка с потерями и балансировкой, неверные кандидаты геолокации, anycast-цель, VPN-режим, история. Специальные цели: blocked.example (цель без ICMP, включается TCP-пинг) и nonexistent.invalid (ошибка DNS).

Настоящее приложение с горячей перезагрузкой интерфейса на Windows:

# терминал 1
cd ui; npm run dev
# терминал 2
$env:MTRTRACER_DEV_URL = "http://localhost:5173"; dotnet run --project src\MTRTracer.App

В dev-режиме в окне работают F12 и Ctrl+R. В обычной сборке инструменты разработчика включаются переменной MTRTRACER_DEVTOOLS=1. На Linux инспектор включает флаг --devtools.

Первый запуск и выбор адаптера

При каждом запуске открывается окно выбора сетевого адаптера. Пакеты трассировки уйдут с адреса выбранного интерфейса, поэтому от выбора зависит, какой маршрут вы увидите.

ВариантЧто происходит
Автопакеты идут так, как решит таблица маршрутизации системы; рядом подписано, через какой адаптер сейчас идёт маршрут по умолчанию
Конкретный адаптерпакеты привязываются к его адресу и выходят через него, даже если маршрут по умолчанию другой (например, Ethernet в обход VPN)
VPN-адаптер + VPN-режимхопы до сервера VPN через физический адаптер и сквозная задержка до цели через туннель (см. VPN-режим)

Для каждого адаптера показаны тип (Ethernet, Wi-Fi, VPN/туннель, виртуальный, мобильный), адреса IPv4 и IPv6, шлюз, DNS-серверы, MAC, скорость, MTU, способ получения адреса и живой трафик. Отметки:

  • Маршрут по умолчанию: через этот адаптер сейчас идёт трафик в интернет;
  • Нет выхода в интернет: у адаптера нет маршрута к внешним адресам, трассировка через него, скорее всего, остановится в локальной сети;
  • у туннелей показан процесс-владелец (например, xray) и физический адаптер, через который туннель работает.

Управление с клавиатуры: ↑ ↓ выбор, Enter подтвердить, Esc закрыть (если трассировка уже идёт). Отключённые и служебные адаптеры спрятаны под ссылкой «Показать отключённые и служебные».

Почему у Ethernet трафика больше, чем у VPN-туннеля? Туннель не имеет своего провода: зашифрованный трафик VPN физически идёт через Ethernet или Wi-Fi. Поэтому счётчики физического адаптера всегда включают в себя весь трафик туннеля.

Подробности хопа

Клик по строке раскрывает детали: график последних 120 пакетов и сводка (min, avg, max, σ, Jint, Jmax), IP и имя, AS с источником данных, префикс и регистратор, провайдер, место с координатами, решение геолокации и физический предел расстояния, последний статус ICMP. Ниже показано, что сказал каждый источник геолокации и почему его приняли или отклонили, с датой получения данных. Если на хопе отвечает несколько узлов, видна доля каждого.

Правая кнопка мыши по строке: трассировать до этого узла, показать подробности, скопировать IP, имя или всю строку.

Сколько строк показывается

Пока цель не ответила, видны хопы до последнего ответившего плюс один (через три раунда плюс три), чтобы было видно, где маршрут обрывается. Когда цель ответила на TTL k, хопы дальше k скрываются и больше не опрашиваются. Если роутер трижды сообщил «недоступно» (сеть, узел, запрещено), маршрут считается законченным на нём.

Как читать результаты

Главное правило MTR: значение имеет только то, что сохраняется до цели. Роутеры обрабатывают ответы на ICMP по остаточному принципу, поэтому их собственные потери и задержки часто выше, чем у транзитного трафика.

КартинаЧто это значит
Потери на хопе 4, дальше 0%ограничение ICMP на роутере, на трафик не влияет
Потери начинаются на хопе N и держатся до целивероятное место проблемы: канал или узел N (или ответный путь)
Хоп «Нет ответа», дальше всё отвечаетроутер не отвечает на ICMP, трафик пропускает; нормально
Резкий рост задержки между хопами и дальше не падаетдлинный магистральный участок (например, между странами) или перегрузка
Задержка выросла на хопе и упала на следующеммедленный ответ самого роутера, не проблема
Высокий Javg у целинестабильная задержка: заметно в играх и звонках
Цель не отвечает на ICMP, TCP-пинг отвечаетузел доступен, ICMP фильтруется
Цель «отвечает» на первом хопе за доли миллисекундыответы подделывает VPN-туннель, нужен VPN-режим

Помните про асимметрию: путь туда и обратно может проходить через разные узлы. Таблица показывает путь туда, а задержка включает оба направления.

Как работает зондирование

Потоки и раунды

На каждый TTL от 1 до максимума запускается свой поток. Поток отправляет пакет (или серию), ждёт ответ не дольше таймаута, затем выдерживает паузу до конца интервала. Старт потоков разнесён на несколько миллисекунд, чтобы 30 пакетов не уходили в одну микросекунду и не упирались в ограничения роутеров. Снимок статистики отправляется в интерфейс не чаще 10 раз в секунду.

Windows

Используется системный ICMP API IcmpSendEcho2Ex (IPv6: Icmp6SendEcho2) в синхронном режиме. Он позволяет задать TTL, флаг DF и адрес источника, поэтому привязка к адаптеру работает без прав администратора. RTT меряется высокоточным таймером (Stopwatch) в микросекундах; время ядра в миллисекундах тоже пишется в лог. Таймер включает около 0.1 мс накладных расходов API.

Linux

Основной способ: непривилегированные ping-сокеты (SOCK_DGRAM + IPPROTO_ICMP), их разрешает настройка net.ipv4.ping_group_range. TTL задаётся опцией сокета, а ответы роутеров «TTL истёк» и «недоступно» приходят в очередь ошибок сокета (IP_RECVERR, чтение через recvmsg(MSG_ERRQUEUE)) вместе с адресом роутера. Если ping-сокеты запрещены, программа пробует raw-сокет (нужно право cap_net_raw) и сама разбирает цитату исходного пакета в ответе. Если не разрешено ни то ни другое, трассировка не стартует и показывает, какую команду выполнить.

Определение цели

Цель считается достигнутой на минимальном TTL, на котором пришёл эхо-ответ от её адреса. Хопы дальше этого TTL перестают опрашиваться и скрываются.

TCP-фолбэк

Если через 4 раунда цель так и не ответила на ICMP, включается TCP-пинг: время установки TCP-соединения с портом из параметров (по умолчанию 443), затем 80 и 22, если предыдущий порт дважды не ответил. Отказ в соединении (RST) тоже считается ответом: узел доступен, порт просто закрыт. Результат показывается отдельной строкой «TCP» под таблицей.

Path MTU

Кнопка во вкладке «Сведения» ищет наибольший пакет, который доходит до цели без фрагментации: двоичный поиск от 576 (IPv6: 1280) до 9000 байт с флагом DF, по две попытки на размер. Значение меньше 1500 обычно означает туннель, PPPoE или VPN.

Обрыв сети

Программа следит за изменениями сетевых адресов. Если выбранный адаптер отключился или потерял адрес, трассировка встаёт на паузу, сверху появляется баннер с таймером, событие пишется в лог. Раз в секунду проверяется, вернулась ли сеть; затем трассировка продолжается сама, привязавшись к новому адресу того же адаптера.

Проверка по скорости света

Свет в оптоволокне проходит около 200 000 км/с, то есть за 1 мс RTT сигнал успевает уйти не дальше примерно 100 км и вернуться. Для каждого кандидата проверяются два условия:

радиус:  d(вы, узел) ≤ 100 км × мин. RTT(этого и всех следующих хопов) + 60 км
объезд:  d(вы, пред.) + d(пред., узел) ≤ 100 км × RTT + 180 км

В радиусе берётся минимум по этому и всем следующим хопам: пакеты к дальним хопам проходят через этот узел, поэтому их быстрый ответ тоже ограничивает его расстояние. Это защищает от медленных ответов роутеров. Учитываются только хопы, по которым пришло хотя бы 2 ответа. «Объезд» требует, чтобы путь через предыдущий размещённый узел тоже укладывался в задержку; это убирает зигзаги.

Выбор и статусы

Из прошедших проверку кандидатов выбирается лучший по весу источника, плюс 1.5 за каждый другой источник в пределах 120 км, минус 3, если известна только страна.

Сводка над картой

Число точек, длина пути по участкам, расстояние по прямой до цели, физический минимум RTT (расстояние × 2 / 200 000 км/с) и измеренный RTT с коэффициентом «во сколько раз путь длиннее идеального». Минимум считается только для подтверждённой цели, поэтому противоречие «измерено меньше физического минимума» невозможно.

Подложка и проекции

По умолчанию карта полностью офлайн: границы стран Natural Earth встроены в программу (упрощённые на мелком масштабе, подробные на крупном). Кнопкой со слоями включается подробная подложка OpenFreeMap из интернета. Есть плоская проекция и глобус. Анимация пакетов рисуется отдельным слоем и ставится на паузу, когда окно свёрнуто.

Ваше местоположение

Все проверки расстояний считаются от точки «Вы». Источники по приоритету:

  1. Вручную: город, выбранный во вкладке «Сведения» → «Ваше местоположение». Самый надёжный вариант, без запросов в сеть.
  2. Cloudflare: speed.cloudflare.com/meta с адреса физического адаптера (не через VPN). Возвращает ваш публичный IP, провайдера, город, координаты и ближайший дата-центр Cloudflare. Результат действует час и только для текущего адаптера и режима.
  3. Первый узел провайдера: если точки нет, отсчёт идёт от первого публичного хопа с надёжным местом.

Защита от подмены местом VPN

  • Адрес Cloudflare резолвится через DNS самого физического адаптера: VPN-клиенты подменяют системный DNS и могут вернуть адреса, работающие только внутри туннеля.
  • Если Cloudflare видит в ответе адрес сервера VPN, место отбрасывается: запрос ушёл в туннель.
  • Если запрос через туннель и напрямую показывает один и тот же IP, место оставляется, но дополнительно проверяется по задержке.
  • Самопроверка: первый близкий публичный роутер (RTT до 30 мс) с надёжным местом должен находиться в пределах физического радиуса от «Вы». Если нет, «Вы» переносится к этому роутеру, а над таблицей появляется предупреждение. Город, указанный вручную, не переносится, только предупреждение.

VPN-режим

Зачем он нужен

Прокси-туннели (Xray, V2Ray, sing-box, Clash/Mihomo, Hiddify, NekoRay, tun2socks) принимают трафик на виртуальный адаптер и передают серверу только TCP и UDP-потоки. Пакет с малым TTL не уходит дальше вашего компьютера, а на эхо-запрос туннель часто отвечает сам за доли миллисекунды. Обычная трассировка через такой адаптер показывает либо одни таймауты, либо «цель на первом хопе за 0.1 мс». Программа это распознаёт (событие «ответы подделаны туннелем») и предлагает VPN-режим.

Как он работает

  1. По таблице соединений ищется процесс известного VPN-клиента и его TCP-соединения с физического адаптера; адрес с наибольшим числом соединений считается сервером. Если не угадал, сервер вписывается вручную во вкладке «Сведения».
  2. До сервера VPN идёт обычная трассировка через физический адаптер: это настоящие хопы вашего провайдера и магистралей.
  3. До самой цели через туннель держится одно постоянное HTTPS-соединение (или HTTP на порту 80, если 443 не отвечает), и раз в интервал отправляется маленький запрос HEAD /. Время от запроса до первого байта ответа и есть настоящая сквозная задержка: этот путь действительно проходит туннель, сервер VPN и интернет до цели.
  4. Через туннель запрашивается Cloudflare, чтобы показать выход VPN: IP, провайдера, город и дата-центр.
  5. Оценка участка «сервер → цель» = минимальный сквозной RTT − минимальный RTT до сервера.

Что видно в интерфейсе

  • Над таблицей: «Через Ethernet: настоящие хопы до сервера VPN …».
  • После хопов строка «Туннель»: IP выхода, провайдер, город, дата-центр Cloudflare и оценка «сервер → цель».
  • Строка цели через туннель: Loss%, Sent, Last, Avg, Best, Worst, Javg, история.
  • На карте: дом → хопы → сервер VPN (квадрат) → пунктирная дуга туннеля → цель.

TCP-соединение через прокси-туннель «устанавливается» за доли миллисекунды: его подтверждает сам туннель. Поэтому VPN-режим меряет задержку по ответу на HTTP-запрос, а не по TCP-рукопожатию. Программа показывает отдельно и время установки TLS.

Ограничения

  • Хопы за сервером VPN не видны никак: это свойство туннеля.
  • UDP-протоколы (WireGuard, Hysteria, TUIC) не видны в таблице TCP-соединений: укажите сервер вручную.
  • Если цель не отвечает ни на 443, ни на 80, сквозная задержка не измеряется.
  • Трассировка до сервера VPN идёт с реального IP, тем же путём, которым VPN-клиент и так подключается к серверу.

DNS и сеть узлов

Резолв цели

  1. Системный резолвер (учитывает hosts, VPN, корпоративные политики), таймаут 4 с.
  2. Если он не ответил: собственный DNS-клиент по UDP к DNS-серверам адаптера, затем к 1.1.1.1, 8.8.8.8, 9.9.9.9, по 2.5 с на запрос; ответ «домен не существует» останавливает перебор.

Каким путём получен адрес и сколько это заняло, видно во вкладке «Сведения». Там же кнопка «Сравнить DNS-серверы»: параллельный запрос ко всем серверам с временем ответа.

Имена узлов

Обратный DNS (PTR) сначала через систему с таймаутом 2.5 с, затем напрямую к DNS-серверам. Запросы асинхронные и кешируются: зондирование не ждёт имён.

AS, префикс, провайдер

Актуальные данные маршрутизации из RIPEstat (network-info и as-overview), при отсутствии сети офлайн-база DB-IP ASN, затем DNS-интерфейс Team Cymru. Источник подписан в подробностях хопа. Провайдер и организация берутся из ip-api.com.

История

Каждая трассировка становится записью в журнале. Снимок пишется раз в минуту и при остановке: итог по цели (потери, avg, best, worst, джиттер), полный список хопов и отпечаток маршрута. Запуски без единого снимка (не стартовали) удаляются. Хранение 180 дней.

  • Список целей слева: время последней проверки, итог и мини-график средней задержки по запускам. Поиск по имени.
  • График средней задержки и потерь по запускам, ось дат.
  • Таблица запусков: когда, сколько длился, режим, адаптер и адрес, avg, best, потери, джиттер, число хопов, маршрут. «Изменился» значит, что набор узлов отличается от предыдущего запуска (по отпечатку основных адресов хопов).
  • Сравнение: отметьте два запуска. Таблица по TTL: узел и avg/потери в каждом запуске, разница; узлы, которые поменялись, подсвечены.
  • Кнопка «Проверить сейчас» запускает новую трассировку этой цели. Правая кнопка мыши: удалить запуск или всю историю цели.

Для VPN-режима в историю пишется сквозная задержка через туннель, а не задержка до сервера.

Права на ICMP

Проверить, разрешены ли ping-сокеты для вашей группы:

cat /proc/sys/net/ipv4/ping_group_range
id -g

Если ваш GID попадает в диапазон, всё работает без root. Если нет, один из вариантов:

# разрешить ping-сокеты всем пользователям (до перезагрузки)
sudo sysctl -w net.ipv4.ping_group_range="0 2147483647"
# навсегда
echo 'net.ipv4.ping_group_range = 0 2147483647' | sudo tee /etc/sysctl.d/60-mtrtracer.conf
# или дать право на raw-сокеты только программе
sudo setcap cap_net_raw+ep ~/.local/opt/mtrtracer/MTRTracer

Право setcap слетает при обновлении файла программы: после переустановки выполните его снова (или ./install.sh --setcap).

Отличия от Windows

  • Окно с обычной рамкой системы, без своих кнопок свернуть и закрыть.
  • Маршруты и адреса: ip route get, интерфейсы классифицируются по имени: en*/eth*, wl*, tun*/wg*/tailscale*, docker*/br-*/veth*.
  • Буфер обмена: браузерный API, иначе wl-copy, xclip или xsel.
  • Экспорт сохраняется в папку загрузок, папки открываются через xdg-open.

Решение проблем

Через VPN все хопы таймаут

Прокси-туннель не пропускает пакеты с малым TTL. Выберите VPN-адаптер и включите VPN-режим, или выберите физический адаптер (Ethernet, Wi-Fi), чтобы увидеть маршрут мимо VPN.

Цель «отвечает» на первом хопе за 0.1 мс

Ответы подделывает туннель. Включите VPN-режим.

VPN-режим: «не удалось определить сервер VPN»

Клиент работает по UDP или не распознан. Возьмите адрес сервера из настроек VPN-клиента и впишите во вкладке «Сведения» → «Сервер VPN».

На карте почти все точки с «?»

Скорее всего, неверно определена точка «Вы». Укажите свой город вручную во вкладке «Сведения» → «Ваше местоположение».

Linux: «Нет прав на ICMP»

Разрешите ping-сокеты или выдайте cap_net_raw, см. Права на ICMP.

Linux: окно не открывается

Нет WebKitGTK 4.1: установите libwebkit2gtk-4.1-0 (Debian/Ubuntu), webkit2gtk4.1 (Fedora), webkit2gtk-4.1 (Arch) или запускайте с --browser.

Windows: пустое окно или сообщение про WebView2

Установите Microsoft Edge WebView2 Runtime. Если окно сообщает, что интерфейс не встроен, пересоберите через build.ps1.

Exe пропал после сборки

Файл не подписан и работает с сетью на низком уровне; антивирус мог поместить его в карантин. Проверьте журнал защиты и добавьте папку сборки в исключения.

Гео-база не скачалась

Строка состояния покажет ошибку. Повторите кнопкой во вкладке «Сведения» → «Геолокация». Без базы программа работает, места узлов берутся из онлайн-источников или имён роутеров.

Адаптер выбран, но «нет маршрута до цели»

У адаптера нет шлюза в интернет (например, виртуальный адаптер Hyper-V). Выберите другой адаптер или «Авто».

«Пакет больше MTU»

Включён флаг DF, а размер пакета больше MTU канала. Уменьшите размер или снимите DF. Узнать точный MTU поможет кнопка Path MTU.
